DEMOGRAPHICS DOMAIN (DM) - 5 Validation Checks
================================================================================

Rule 1: SUBJECT_ID Uniqueness
  Objective: One demographic record per subject
  Check: DUPLICATED(SUBJECT_ID) = FALSE
  Failure: DQ_SUBJECT_DUPLICATE = 1
  Action: Report to data coordinator — resolve before analysis

Rule 2: AGE Presence
  Objective: All subjects must have age documented
  Check: AGE IS NOT NULL
  Failure: DQ_AGE_MISSING = 1
  Action: Query source — essential for baseline characterization

Rule 3: AGE Range
  Objective: Valid adult age
  Range: 18 ≤ AGE ≤ 100
  Failure: DQ_AGE_RANGE = 1 (if age < 18 OR > 100)
  Rationale: Lower bound = study enrollment criterion; upper bound = outlier detector
  Action: Investigate; could be data entry error (e.g., 51 vs 156)

Rule 4: SEX Standardization
  Objective: Consistent sex values
  Valid Values: M, F (standardized to uppercase)
  Failure: DQ_SEX_INVALID = 1 (if not in {M, F})
  Examples of Invalid: "Male", "UNKNOWN", "1", "2", NULL
  Action: Standardize to M/F or query if ambiguous

Rule 5: ENROLL_DATE Presence
  Objective: Study enrollment date required for all subjects
  Check: ENROLL_DATE IS NOT NULL
  Failure: DQ_ENROLL_DATE_MISSING = 1
  Action: Essential for visit window calculations; must be sourced


VITAL SIGNS DOMAIN (VS) - 12 Validation Checks
================================================================================

Missing Value Checks (4 checks)
─────────────────────────────────
  Check 1: SYSTOLIC_BP IS NOT NULL → DQ_SYSTOLIC_MISSING
  Check 2: DIASTOLIC_BP IS NOT NULL → DQ_DIASTOLIC_MISSING
  Check 3: HEART_RATE IS NOT NULL → DQ_HEART_RATE_MISSING
  Check 4: TEMP_C IS NOT NULL → DQ_TEMP_MISSING
  
  Action if failed: Report missing; may accept if medically justified


Range Validation Checks (4 checks)
─────────────────────────────────
  Check 5: SYSTOLIC_BP Range
    Valid: 70 ≤ SYSTOLIC_BP ≤ 250
    Failure: DQ_SYSTOLIC_RANGE = 1
    Rationale: <70 mmHg = shock; >250 mmHg = hypertensive emergency
    
  Check 6: DIASTOLIC_BP Range
    Valid: 40 ≤ DIASTOLIC_BP ≤ 150
    Failure: DQ_DIASTOLIC_RANGE = 1
    Rationale: <40 mmHg = severe hypotension; >150 mmHg = severe HTN
    
  Check 7: HEART_RATE Range
    Valid: 30 ≤ HEART_RATE ≤ 220
    Failure: DQ_HEART_RATE_RANGE = 1
    Rationale: <30 bpm = extreme bradycardia; >220 bpm = extreme tachycardia
    
  Check 8: TEMP_C Range
    Valid: 34 ≤ TEMP_C ≤ 42
    Failure: DQ_TEMP_RANGE = 1
    Rationale: <34°C = mild hypothermia; >42°C = life-threatening fever


Logic Validation Checks (2 checks)
──────────────────────────────────
  Check 9: Blood Pressure Relationship
    Logic: DIASTOLIC_BP < SYSTOLIC_BP
    Failure: DQ_BP_LOGIC = 1 (if DIASTOLIC ≥ SYSTOLIC)
    Note: Diastolic pressure is measured during relaxation phase; 
          must be lower than systolic
    Example Catch: Transposed values (120/90 vs 90/120)
    
  Check 10: VISIT_DATE Presence
    Check: VISIT_DATE IS NOT NULL
    Failure: DQ_VISIT_DATE_MISSING = 1
    Requirement: Essential for visit window validation


Date Sequence Checks (2 checks)
──────────────────────────────
  Check 11: Visit Date vs Enrollment Date
    Logic: VISIT_DATE ≥ ENROLL_DATE
    Failure: DQ_VISIT_BEFORE_ENROLL = 1
    Purpose: Prevent phantom pre-enrollment visits


ADVERSE EVENTS DOMAIN (AE) - 5 Validation Checks
================================================================================

Rule 1: AE Term Presence
  Objective: Every adverse event must have a term
  Check: AETERM IS NOT NULL
  Failure: DQ_AE_TERM_MISSING = 1
  Action: Critical for coding; cannot proceed without term

Rule 2: START_DATE Presence
  Objective: Adverse event onset date required
  Check: START_DATE IS NOT NULL
  Failure: DQ_START_DATE_MISSING = 1
  Action: Query source — temporal information essential

Rule 3: SEVERITY Presence
  Objective: All AEs must be graded
  Check: SEVERITY IS NOT NULL
  Failure: DQ_SEVERITY_MISSING = 1
  Action: Required for risk assessment

Rule 4: SEVERITY Standardization
  Objective: Consistent severity grading
  Valid Values: MILD, MODERATE, SEVERE
  Failure: DQ_SEVERITY_INVALID = 1 (if not in valid list)
  Examples of Invalid: "MINOR", "Grade 1", "1", "LIFE-THREATENING"
  Action: Standardize to MILD/MODERATE/SEVERE

Rule 5: Date Sequence (Start ≤ End)
  Objective: Adverse event must resolve after onset
  Logic: END_DATE ≥ START_DATE (or END_DATE IS NULL for ongoing)
  Failure: DQ_DATE_LOGIC = 1
  Example Catch: AE from 2026-08-10 to 2026-08-05 (reversed)
  Action: Query source for correct dates


LABORATORY RESULTS DOMAIN (LB) - 4 Validation Checks
================================================================================

Rule 1: RESULT Presence
  Objective: Numeric result required
  Check: RESULT IS NOT NULL
  Failure: DQ_RESULT_MISSING = 1
  Action: Query for missing lab result

Rule 2: RESULT Validity (Numeric)
  Objective: Result must be convertible to number
  Check: RESULT IS NUMERIC
  Failure: DQ_RESULT_INVALID = 1
  Examples of Invalid: "HIGH", ">500", "PENDING", "ND" (not done)
  Action: Clarify with site; may need code as non-numeric comment

Rule 3: UNIT Presence
  Objective: All results must have units
  Check: UNIT IS NOT NULL
  Failure: DQ_UNIT_MISSING = 1
  Examples: "mg/dL", "IU/L", "mmol/L", "cells/μL"
  Action: Essential for result interpretation

Rule 4: Reference Range Derivation
  Objective: Flag clinically abnormal results
  Logic: 
    IF RESULT < NORMAL_LOW → LBNRIND = "LOW"
    IF RESULT > NORMAL_HIGH → LBNRIND = "HIGH"
    ELSE → LBNRIND = "NORMAL"
